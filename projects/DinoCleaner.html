DinoCleaner 진행중

3D · 세차 시뮬레이션 · Single Play · Unity

프로젝트 소개

4인 팀 · 2026-2 컴퓨터게임설계 수업 프로젝트 · 2026.09 ~ 진행중

 진흙으로 뒤덮인 공룡들을 직접 씻겨 깨끗하게 만드는 3D 세차 시뮬레이션 게임입니다. 공룡 표면의 오염이 씻어 낸 자리만큼 실시간으로 지워지고, 공룡의 각 부위별로 얼마나 깨끗해졌는지 확인하며 청소를 완료해 나갑니다.
 저는 게임의 핵심인 청소 시스템을 맡아, 텍스처 기반 오염 표현부터 청소 진행도 계산까지 설계하고 구현하고 있습니다.

나의 역할

청소 시스템 담당

  • RenderTexture 기반 오염 마스크와 GPU 페인팅 셰이더 구현
  • AsyncGPUReadback을 이용한 전체·부위별 청소 진행도 계산
  • Assembly Definition으로 Core / Cleaning / Player / UI 모듈 구조 설계
  • 청소 인터페이스(ICleanable, ICleanProgress)와 EventBus 설계로 다른 팀원 파트와 연결

Technical issues

메쉬를 UV 공간에 펼쳐 오염 지우기

공룡마다 오염 상태를 저장하는 마스크 텍스처(RenderTexture)를 두고, 버텍스 셰이더에서 UV 좌표를 화면 좌표로 사용해 메쉬를 텍스처 위에 펼쳐 그렸습니다. 각 픽셀은 자신의 월드 좌표와 브러시 위치 사이의 거리로 지울 양을 계산하기 때문에, UV가 끊긴 경계와 상관없이 3D 표면 기준으로 자연스럽게 지워집니다.

CommandBuffer로 GPU에서 한 번에 처리

같은 텍스처를 읽으면서 동시에 쓸 수 없는 문제를 피하기 위해, 매 스트로크마다 현재 마스크를 복사본에 옮긴 뒤 복사본을 읽고 원본에 쓰도록 했습니다. 복사, 브러시 정보 전달, 렌더러별 그리기 명령을 CommandBuffer에 모아 GPU에 한 번에 실행합니다.

AsyncGPUReadback으로 진행도 비동기 측정

진행도를 알려면 GPU에 있는 마스크를 CPU에서 읽어야 하는데, 동기로 읽으면 프레임이 멈춥니다. 1024 해상도 마스크를 GPU 안에서 256으로 축소해 전송량을 줄이고, AsyncGPUReadback으로 몇 프레임 뒤 결과를 받도록 했습니다. 측정은 마스크가 바뀌었을 때만 0.25초 간격으로 요청해 불필요한 연산을 줄였습니다.

부위 맵을 이용한 부위별 진행도

UV 공간에 부위 번호를 색으로 칠한 부위 맵 텍스처를 만들고, 축소 단계에서 오염 값과 부위 번호를 한 픽셀에 함께 담아 부위별 진행도를 한 번에 계산합니다. 부위 청소가 끝나면 EventBus로 완료 이벤트를 보내 UI 등 다른 시스템이 구독할 수 있게 했고, 부위 맵의 sRGB·압축·필터 설정이 잘못되면 시작할 때 경고를 띄워 팀원의 설정 실수를 미리 잡도록 했습니다.

Assembly Definition으로 모듈 의존성 정리

5명이 동시에 작업하는 만큼 코드 간 의존성이 꼬이지 않도록, Core 어셈블리에는 인터페이스와 데이터 구조만 두고 Player와 UI는 Core만 참조하게 나눴습니다. 덕분에 플레이어 쪽은 청소 구현을 몰라도 ICleanable에 스트로크만 전달하면 되고, UI는 ICleanProgress만 보고 진행도를 표시할 수 있습니다.
