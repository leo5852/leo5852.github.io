Technical issues

MVC 구조의 맵 에디터

탑뷰와 사이드뷰 두 시점을 나란히 띄워 놓고 클릭만으로 타일과 아이템을 배치하는 에디터를 만들었습니다. 맵 데이터(EditorMapData), 화면 표시(EditorView), 입력 처리(EditorInputController)를 분리하고, 데이터가 바뀌면 이벤트로 화면에 알리도록 해 기능을 추가해도 서로 영향을 덜 받게 했습니다.

비개발자의 실수를 막는 배치 규칙

플레이어와 문은 맵에 하나만 있도록 새로 놓으면 기존 것을 자동으로 지우고, 시점에 맞지 않는 오브젝트는 배치를 막고 맨 위·아래 줄에는 빙판만 놓을 수 있게 했습니다. 포탈은 하나를 놓으면 같은 색의 짝을 놓을 때까지 강제 모드를 유지하고, 중간에 취소하면 짝 없는 포탈을 함께 정리해 깨진 스테이지가 저장되지 않게 했습니다.

두 시점을 잇는 3D 아이템 배치

양쪽 시점에 모두 보이는 아이템은 탑뷰에서 고른 X·Z 좌표와 사이드뷰에서 고른 Y 좌표를 합쳐 실제 3D 위치를 만듭니다. 첫 클릭 후에는 반대편 화면에 놓을 수 있는 영역을 하이라이트로 안내하고, 이미 놓인 아이템이나 포탈에 마우스를 올리면 반대편 위치와 짝을 선으로 보여 줘 두 시점의 관계를 한눈에 확인할 수 있게 했습니다.

JSON 저장과 에디터 내 테스트 플레이

완성한 맵은 Json.NET으로 직렬화해 저장하고 게임에서 그대로 불러옵니다. Vector3를 직렬화할 때 생기는 순환 참조 문제는 커스텀 컨버터로 해결했고, 2차원 타일 배열은 한 행을 한 줄로 저장해 파일을 열어도 맵 모양이 보이도록 했습니다. 여기에 팀원이 만든 테스트 플레이 기능을 연결해 에디터에서 바로 플레이해 볼 수 있게 했고, 덕분에 기획·아트 팀원이 직접 스테이지를 만들며 UNICON 출품 전 스테이지를 25개에서 50개로 늘릴 수 있었습니다.

허브 스테이지와 해금 연동

스테이지 선택 화면을 캐릭터가 직접 걸어 다니며 고르는 허브 스테이지로 구현했습니다. 블루가 에피소드 문에 들어가면 핑크 쪽 스테이지 문 10개가 세이브 데이터의 해금 상태에 맞춰 잠기거나 열리고, 문 앞에 2초간 머무르면 입장합니다. 진행 상황은 JSON으로 저장되고, 테스트용 DevMode에서는 모든 문이 열립니다.

AudioMixer 기반 볼륨과 음소거

마스터, BGM, 효과음을 AudioMixer 그룹으로 나누고, 슬라이더 값(0~1)을 log10 × 20으로 데시벨로 바꿔 귀로 듣기에 자연스럽게 볼륨이 변하도록 했습니다. 음소거할 때는 채널별로 이전 볼륨을 저장해 두었다가 해제하면 그대로 복원합니다.
